## 设置与数据边界

设置目录由开发者维护，位于 `catalog.go`。`page` 指明显示在哪个分类，`section` 指明分类内的设置组，`group` 指明配置归属；显示分类与写入来源是两个概念。例如“窗口与工作区”同时包含 niri 主配置和 DMS 管理的布局设置，不能把整个分类直接写进同一个文件。

| 分类 | 已登记后端能力 | 保存来源 |
| --- | --- | --- |
| 窗口与工作区 | 间距、边框、圆角；聚焦列居中、单列居中；概览关闭行为；工作区编号、名称、应用图标、滚轮切换和仅显示占用工作区 | niri 主配置或 DMS 受限设置接口 |
| DMS 外观 | 动画、圆角、减少动态效果、点击反馈、不透明度、时钟、周数、通知时长与声音 | DMS 受限设置接口 |
| 电源与会话 | 接电和电池各自的息屏、锁屏、睡眠、锁后息屏计时；睡眠方式；锁屏集成与渐暗宽限 | DMS 受限设置接口 |
| CachyOS 集成 | 8 项配置保护及文件状态；5 项用户服务只读状态 | 已核实的 cachyos-config protect/unprotect；systemctl 只读查询 |

工作区显示选项控制 DMS 状态栏中的工作区组件，不创建或重命名 niri 工作区。没有放置该组件时只能说明配置已保存，不能声称屏幕已经显示这些信息。

空闲计时以整数秒保存，0 关闭对应的自动动作。自定义时间不能错误显示成“从不”。渐暗宽限发生在空闲阈值之后，渐暗本身不等于已经安全锁屏。

运行状态由桌面桥接只读返回，桥接是插件在 DMS 内提供的固定方法，用于读取 DMS 已有的空闲、电池和会话服务。缺少字段时标记 `unreachable / runtime_unavailable`，不把缺失当作 false。系统支持情况通过登录管理器的只读接口检查，不执行挂起或休眠试验。

## 保存规则

1. niri 主配置和包含文件共同参与修订校验。新增窗口项按具体配置路径确认归属；其他包含文件有布局间距或输入设置，不会因此错误禁止主配置的独立居中规则。目标规则出现在包含文件时拒绝跨文件覆盖。
2. DMS 写入入口从设置目录查找允许的键，同时校验类型、选项、整数和范围。加载中、解析错误、只读、尚有未保存更改时拒绝写入。
3. DMS 内存回读之后，比较 DMS 导出的持久化表示与磁盘文件中的对应键。DMS 会省略默认值，所以还要比较键是否存在，不能猜默认值，也不能把内存成功直接当作磁盘成功。
4. 配置保护只接受固定 ID 和布尔值。目标必须在安装器清单登记，路径不得包含符号链接；不接收请求提供的文件路径。保护状态和文件是否存在分别返回。
5. 保护清单先备份，逐项调用后回读。中途失败只报告已经确认的项目；修订变化时保留其余草稿。不调用 update/migrate，不改系统安装资源。

## 实现与验收

- 分类和分组使用正式 QML 页面，复用既有设置组、行、开关与下拉框。
- 只提交、放弃和核对当前分类的草稿；跨来源时按顺序保存，部分失败保留其余草稿。其他分类的错误不阻止本页保存。
- 自定义秒数、文件状态、运行抑制状态和服务详情的可视化。
- 已完成本机安装、DMS 实际加载和指定插件窗口截图检查。低分辨率检查使用单独的验收窗口，只改变该临时窗口的尺寸。

本轮验证没有改变用户的窗口、电源或保护策略，没有触发锁屏、挂起和休眠。真实写入流程通过包内隔离配置与模拟 DMS 校验；本机验收只读检查与编辑/放弃草稿，没有执行实际锁屏、睡眠或改变用户保护状态。
