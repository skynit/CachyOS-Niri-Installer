# 桌面设置

本机 DMS 插件，以用户批准的 V5 浅色设置界面为基准。状态栏提供入口，设置编辑器是可平铺、浮动和缩放的独立窗口。仅打开窗口或编辑草稿不会改变桌面配置；点击应用才提交设置。

2026-10-20 已按确认的“桌面与系统”预览完成插件内页面，并安装 0.2.0。本轮保留 Qoder 浅色基准；新增项先进入当前分类草稿，点击应用才保存。细节和验证边界见 [design/SYSTEM.md](design/SYSTEM.md)。

## 组件与职责

窗口颜色实时跟随 DMS 的明暗模式，复用现有浅色与深色配色，不再保存独立的插件明暗开关。右上角太阳／月亮按钮通过 DMS 的主题接口切换桌面模式；从其他入口切换明暗时，已打开的窗口也会同步，窗口草稿不会因此重置。屏幕背光亮度与明暗主题是独立设置。

- DMS（DankMaterialShell）是用户安装的桌面外壳，由它加载插件、显示状态栏入口并提供原有设置界面；它与负责窗口和输入设备的 niri 不同。
- QML 是 DMS 使用的界面语言。开发者编写的 `SettingsWindow.qml` 组织导航、页面、草稿提示和显示确认；`SettingRow.qml` 根据设置定义选择滑块、数字框、开关或下拉框。相同控件复用于不同设置，不为每项另写一套界面。
- 设置目录是开发者维护的受限设置清单，位于 `catalog.go`，记录名称、类型、范围、选项和配置节点位置。增加设置先登记这里，再接入必要的读写规则；界面不接受任意文件路径或命令。
- Go 辅助程序是随插件构建的本地可执行文件，负责真实读取、参数校验、并发修改检查、备份和保存。`SettingsSource.qml` 只通过参数数组和 JSON 标准输入调用它，不拼接用户输入到 shell。
- 草稿是界面尚未应用的值，保存在当前插件进程中；切换分类和关闭窗口会保留，DMS 重启后不保留。已保存配置、草稿和当前显示器运行状态分别展示。
- KDL 是 niri 使用的配置文本格式。`kdl.go` 记录节点在原文本中的位置，只替换目标节点，因此保留其他节点、注释和 include 声明。它是本插件受限的编辑扫描器，不是完整 KDL 语言实现；遇到无法安全理解的写法时拒绝编辑。
- include 是 niri 配置引用其他配置文件的声明，由用户、安装器或 DMS 配置。辅助程序会读取这些文件并计算内容修订标识；被引用文件变化也会使旧草稿的写入被拒绝。若输入或显示设置由 include 文件管理，插件拒绝直接改写，提供 DMS 对应设置入口。
- 显示恢复任务是辅助程序通过 systemd 创建的独立用户服务。systemd 是本机服务管理器；这个任务有独立的进程分组，不随 DMS 服务重启一起被终止。QML 倒计时只负责展示，后台保存的截止时间负责恢复。
- 能力状态保留 `healthy`、`degraded`、`unsupported`、`unreachable`，并显示原因。读取失败时不把旧值当作新事实，也不清空草稿。

## 应用流程

1. 打开窗口后读取 niri 主配置、include 文件、真实显示输出、登记的 DMS 设置和 CachyOS 保护状态。输入设备运行状态未接入，界面对此有明确说明。
2. 用户修改只更新当前分类草稿，数字框检查范围、整数与有效数值。分类切换不会应用或丢弃草稿；放弃修改也只作用于当前分类。窗口分类有两个来源时先处理 niri，再处理 DMS。失败停止后续请求，只清除已确认的项目。各分类分别保留修订基准，重新读取不会静默接受外部修改。
3. 提交 niri 设置时，比较读取时的修订标识，生成临时配置，在主配置同目录执行 `niri validate -c`。校验失败不写入。
4. 需要时先执行已核实的 `cachyos-config protect`，然后保存权限为 0600 的备份，再次检查配置是否变化，原子替换主配置并回读。该过程不代表输入设备运行效果已验收。
5. DMS 设置使用 `settings get` 读取，通过插件的 `desktopSettings setValue` 接口写入。该接口从 Go 设置目录读取允许的键，验证类型、范围和选项，将 JSON 值解析成原始类型，再调用 DMS 的 `SettingsData.set`；这是 DMS 自身维护的设置方法，会保存配置并触发布局重新生成等对应动作。提交前备份本次涉及键的原值，逐项检查、内存回读和磁盘核对。默认值可能被 DMS 省略，因此同时比较持久化表示中键是否存在。负数 JSON 参数放在命令选项终止符 `--` 后，避免被命令行误当成选项。DMS 接口没有跨键原子事务，部分成功时只清除已确认项的草稿，保留未完成项并报告结果。
6. 显示设置先登记恢复会话并启动独立用户服务，收到就绪标记后才调用 `niri msg output` 临时切换。实际输出必须与目标一致，才显示确认入口。
7. 用户在 20 秒内确认后才校验、备份并保存输出配置。超时或窗口关闭会恢复原显示状态；DMS 退出时恢复任务也会继续。恢复失败保留错误与记录，不能显示为恢复成功。

配置并发检查是基于内容快照与本插件操作锁的检查；外部程序不共享该锁，DMS 接口也没有原子比较并写入功能，因此不承诺与外部编辑器之间的完全原子事务。

## 构建、安装与入口

构建需要 Go；运行需要 DMS 1.6.2、niri 与 `systemd-run`。CachyOS 保护使用本机 `cachyos-config`；服务状态和睡眠能力查询使用 systemd 提供的 `systemctl`、`busctl`，这些能力不可达时如实返回原因。构建和安装脚本还使用 Bash、coreutils、ripgrep。插件运行不需要 Node、React、Python 或网络服务。

```bash
cd /home/skynit/workspace/dms-plugins/DesktopSettings
bash build.sh
bash install.sh
dms ipc call plugin-scan scan
dms ipc call plugins enable desktopSettings
dms ipc call desktopSettings open
dms ipc call desktopSettings addToBar
```

更新已安装副本后使用 `dms ipc call plugin-scan rescan desktopSettings`。安装脚本只复制运行文件，并检查已有副本的文件摘要；发现本地修改时停止覆盖。构建脚本在 amd64 上显式使用 `GOAMD64=v1`、`CGO_ENABLED=0`。

修改 QML 后还需调用 `dms ipc call plugin-scan reload desktopSettings`。若界面仍使用缓存中的旧子组件，需要刷新 DMS 外壳后重新打开插件。`addToBar` 仅向已启用的普通状态栏加入自身入口；当前若只有岛式栏，会返回 `BAR_UNAVAILABLE`，可继续从 DMS 插件设置页打开窗口。

状态栏入口是“桌面设置”小组件；DMS 插件设置页也有打开按钮。独立窗口支持 Tab、Enter/Space，以及原生滑块和下拉控件的箭头操作。不增加全局 Mod/Super 快捷键。

```bash
dms ipc call desktopSettings status
dms ipc call desktopSettings close
dms ipc call desktopSettings openPage power
```

主配置固定为当前用户配置目录下的 `niri/config.kdl`。设置了其他 `NIRI_CONFIG` 路径时拒绝猜测写入。备份与记录位于 `${XDG_STATE_HOME:-$HOME/.local/state}/DankMaterialShell/DesktopSettings/`，显示会话文件也放在此目录。插件不读取剪贴板，不修改 `/etc`，不提权。

## 验证范围

```bash
go test .
GOAMD64=v4 bash build.sh
go version -m desktop-settings-helper
./desktop-settings-helper snapshot
```

单元测试与真实 niri 临时文件校验集中在 `main_test.go`，覆盖注释与禁用节点、非法值、include 所有权与修订、备份、校验失败、外部修改、输出模式、过期恢复、DMS 部分结果与磁盘保存核对、新目录校验、窗口具体节点归属、保护备份和部分失败，以及实际 QML JavaScript 的受限写入、分类草稿和跨来源队列。测试中的 Node 仅用于执行界面脚本契约，不是插件运行依赖。只测试当前插件包。

另已用隔离的 LAB-1 文件模拟器运行真实 systemd 用户恢复任务，验证父进程退出后的超时恢复和确认后的保存。该验证没有调整本机实际输出。真实单内屏读取与 QML 渲染另行检查；真实外接显示器切换、断连与镜像仍未验收。

视觉基准和历史设计在 `design/`。`input-v5-*` 为手工绘制的批准稿，`runtime-*` 为实际 QML 窗口截图，两者不能混称。

本轮额外使用隐藏的 Quickshell 验收实例和临时模拟辅助程序，确认真实 QML 进程完成两段保存后，只清除当前窗口分类的草稿、保留其他分类草稿；该模拟没有接触用户配置。另用真实辅助程序检查新增页面、服务状态和空闲抑制状态，按窗口 ID 截图检查 960×640、1280×800 和 1440×900 的布局。图片保留物理像素，当前显示缩放为 1.75，因此图片尺寸与逻辑窗口尺寸不同，没有将缩放图片冒充原始截图。

本机读回确认原有设置未因开发验证改变；没有实际试锁屏、挂起、休眠、配置保护写入或外屏切换。安装与定向重载后确认旧子组件缓存仍在，检查无草稿且启动锁屏关闭后刷新过一次 DMS。后续修改文档或 Go 辅助程序不要求重启外壳。
